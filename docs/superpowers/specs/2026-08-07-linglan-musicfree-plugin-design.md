# 设计：聆澜 MusicFree 兼容插件接入与平台解耦

日期：2026-08-07  
状态：已与用户确认，待额度重置后实施

## 1. 背景与目标

简云音乐当前仍以网易云音乐的数据模型、接口、登录态和歌曲 ID 为核心，并在播放失败时调用聆澜或酷狗兜底。目标是把应用改造成一个通用音乐播放器和插件宿主：在线曲库由用户自行购买并授权的聆澜 MusicFree 兼容插件提供，简云仓库和安装包不再内置网易云接口、聆澜脚本或用户密钥。

本方案参考 MusicFree 的插件宿主思路，但采用独立实现，不复制 MusicFree 的 AGPL-3.0 源代码，以保持当前项目许可证边界清晰。

## 2. 已确认的产品决策

1. APK 只包含通用播放器、通用数据模型和 MusicFree 兼容插件宿主。
2. 聆澜脚本不提交到简云仓库，也不打包进 APK。
3. 应用不内置固定聆澜密钥。用户购买后，在设置页输入自己的密钥。
4. 密钥由聆澜服务端验证；应用不把“本地解析密钥”当作授权依据。
5. 验证通过后，应用从聆澜获取插件清单，并在运行时下载用户选择的脚本。
6. 设置页一次选择一个当前在线音乐来源。新的搜索和浏览使用该来源；收藏、历史和歌单允许同时包含多个来源，歌曲始终保留实际来源的复合主键。
7. 不做跨来源合并搜索，也不拼接不同来源的封面或歌词；播放时先按歌曲自己的 `pluginId` 恢复缓存或从当前已授权清单按需装载对应来源，仍解析失败时才用“规范化歌名完全一致、至少一位歌手一致、时长差不超过阈值”的严格规则查询其他可用来源，并把实际命中的歌曲作为播放、收藏、歌词和历史实体。
8. 歌曲所属插件缺少封面或歌词时显示默认内容；跨来源播放成功时明确提示实际来源，未达到严格匹配条件时保留原错误，禁止猜测播放。
9. Bilibili 和 GitCode 不进入音乐来源选择列表，也不参与资源获取。
10. 本地音乐、本地歌单、播放历史等本地能力不依赖聆澜授权。
11. 远程 JavaScript 使用轻量隔离的 QuickJS 上下文运行，不使用带有宽泛 Android JS Bridge 的 WebView，也不允许脚本直接访问 Android 系统能力。
12. “移除网易云关联”是指移除 APK 内置的网易云 API、登录、Cookie、数据模型和兜底逻辑；如果聆澜清单中存在网易云插件，用户仍可主动选择它。此时简云只把它视为普通的第三方插件，不包含该平台的专用实现或默认优先级。
13. 首个版本隐藏依赖网易云相似歌曲或推荐歌单接口的在线推荐入口，只保留不需要平台接口的本地最近播放、收藏和本地统计；推荐系统以后另行设计。
14. 简云自有内容和本地音乐不进入聆澜来源单选列表，可与当前在线插件同时存在。

## 3. 非目标

- 不做宽松的多来源聚合、无条件自动择优或只凭歌名的跨来源兜底。
- 不在应用中提供、售卖或转发第三方平台账号、Cookie 或会员权益。
- 不把聆澜脚本内容、接口响应样本或个性化下载地址提交到仓库。
- 不承诺插件可以绕过第三方平台的地区、会员、版权或访问限制。
- 本文档不替代对聆澜授权协议、第三方平台条款和应用商店政策的法律审查。
- 本次只完成设计，不改动现有业务代码。

## 4. 总体架构

```text
设置页
  ├─ 输入并验证聆澜密钥
  ├─ 拉取、过滤插件清单
  └─ 选择一个当前音乐来源
          │
          v
LinglanCredentialStore ── LinglanManifestClient
          │                       │
          └──────────┬────────────┘
                     v
              PluginRegistry
                     │
          下载、校验、缓存、装载
                     v
       QuickJS PluginRuntime（轻量隔离）
                     │
        MusicProvider 统一 Kotlin 接口
          ├─ 搜索/详情/专辑/歌手/歌单
          ├─ 封面/歌词
          └─ 解析播放地址及请求头
                     │
                     v
       Repository / ViewModel / Player
```

核心边界如下：

- 简云负责 UI、播放器、本地数据、下载、缓存、插件运行环境和错误展示。
- 聆澜负责密钥有效性、插件清单和脚本分发。
- 被选择的插件负责在线曲库能力和远程媒体地址解析。
- 播放器只消费已解析的媒体描述，不感知网易云、QQ、酷狗等平台细节。

## 5. 核心领域模型

当前 `Song.id: Long` 无法容纳不同平台的字符串 ID，也无法避免跨来源 ID 冲突。新模型必须把来源身份作为主键的一部分。

```kotlin
data class PluginDescriptor(
    val id: String,
    val name: String,
    val version: String,
    val protocolVersion: Int,
    val minHostVersion: String?,
    val downloadUrl: String,
    val category: PluginCategory,
    val integrity: String?,
    val status: PluginReleaseStatus,
)

data class ProviderTrackKey(
    val pluginId: String,
    val remoteId: String,
)

data class OnlineTrack(
    val key: ProviderTrackKey,
    val producedByPluginVersion: String,
    val payloadSchemaVersion: Int,
    val title: String,
    val artists: List<OnlineArtist>,
    val album: OnlineAlbum?,
    val durationMs: Long?,
    val artworkUrl: String?,
    val pluginPayload: BoundedJsonObject,
)

data class ResolvedMedia(
    val url: String,
    val headers: Map<String, String>,
    val userAgent: String?,
    val quality: String?,
    val expiresAtEpochMs: Long?,
)
```

约束：

- 收藏、历史、队列、缓存和下载记录都以 `pluginId + remoteId` 标识在线歌曲。
- 插件后续调用需要的附加字段放在经过清洗、可序列化且有大小和层级上限的 `pluginPayload` 中，不能把整个脚本返回对象无限制持久化，也不能保留密钥、授权头或个性化脚本 URL。
- `PluginDescriptor.downloadUrl` 只存在于清单获取和下载过程的内存中；如果 URL 含用户凭据，不得持久化到普通设置、数据库或诊断信息。
- 持久记录保存产生它的插件版本和宿主 payload schema 版本。新版插件必须通过旧 payload 契约测试；若不兼容，则使用未被撤销的上一个已知可用版本，仍不兼容时把条目标记为需要重新搜索，不能猜测转换。
- 播放地址通常具有时效性，不作为歌曲实体永久保存；临近播放时解析，并按过期时间缓存。
- 日志和分析事件不得记录密钥、带密钥的 URL、完整播放地址或插件脚本正文。

### 5.1 稳定插件 ID

在写入任何收藏、历史、队列或下载记录前，`PluginRegistry` 必须得到稳定 ID。优先使用聆澜清单提供的不可变 ID；当前清单没有该字段时，应用使用版本化的内置精确映射，例如将已批准的清单主机、去除查询参数后的固定路径和来源类型映射到 `linglan.kg`、`linglan.kw`、`linglan.tx`、`linglan.wy`。显示名、密钥、查询参数和脚本版本都不参与 ID 计算。

无法命中稳定映射的清单项不允许产生持久数据。映射变更必须附带数据库迁移，不能在运行时临时哈希一个可能变化的 URL。

## 6. MusicFree 兼容插件协议

首版宿主实现 MusicFree 插件常用的 CommonJS 形态，并以能力检测为准，不假设每个插件都实现全部方法。

### 6.1 插件入口与元数据

脚本通过 `module.exports` 导出插件对象。宿主读取并验证以下信息：

- `platform`
- `version`
- `supportedSearchType`
- 可选的能力声明和请求头配置

插件 ID 由清单中的稳定 ID 或第 5.1 节的版本化精确映射决定，不使用可变的中文显示名、脚本版本、查询参数或临时下载地址作为数据库主键。

### 6.2 首版支持的方法

宿主内部先冻结 `JianyunMusicFreeCompat/1` 契约。以下 JavaScript 调用都允许直接返回值或 Promise；抛出异常和 rejected Promise 统一转换为带 `code`、可展示消息和可重试标记的宿主错误。页码从 1 开始，缺失列表按空列表处理，但 ID、标题等必需字段缺失时拒绝该条结果。

| 能力 | JavaScript 调用 | 归一化返回 |
|---|---|---|
| 搜索 | `search(query, page, type)` | `{ data: Item[], isEnd: boolean }` |
| 播放 | `getMediaSource(musicItem, quality?)` | `{ url, headers?, userAgent?, quality?, expiresAt? }` |
| 歌词 | `getLyric(musicItem)` | `{ rawLrc?, translation?, romaLrc?, wordLrc? }` |
| 专辑 | `getAlbumInfo(albumItem, page?)` | `{ albumItem?, musicList: MusicItem[], isEnd? }` |
| 歌手 | `getArtistWorks(artistItem, page, type)` | `{ data: Item[], isEnd: boolean }` |
| 歌单 | `getMusicSheetInfo(sheetItem, page)` | `{ sheetItem?, musicList: MusicItem[], isEnd? }` |
| 榜单 | `getTopLists()` | 分组榜单列表 |
| 榜单详情 | `getTopListDetail(topListItem)` | `{ topListItem?, musicList: MusicItem[] }` |

`type` 只接受宿主定义并被 `supportedSearchType` 声明支持的 `music`、`album`、`artist`、`sheet` 等值。输入 item 由宿主从标准字段和该条目的受控 `pluginPayload` 重建；插件返回对象必须经过适配器复制，JavaScript 对象本身不能跨上下文或进入数据库。

分页字段、歌词字段别名、艺术家/专辑形态和媒体请求头的详细映射写入独立的 `JianyunMusicFreeCompat/1` 契约测试规范。阶段 0 必须用当前允许来源的脱敏结构样本验证并冻结该规范；真实插件出现未覆盖差异时，通过版本化适配器扩展，不能在 Repository 中加入平台名称判断。

若插件缺少某项能力，UI 隐藏对应入口或显示“当前来源不支持”，不能调用另一个来源补齐。

### 6.3 JavaScript 依赖兼容层

已观察到的聆澜脚本可能依赖 `axios`、`crypto-js`、`qs`、`big-integer`、`dayjs`、`cheerio` 和 `he`。实施前要制作一张“实际脚本依赖—宿主实现”清单，并优先提供小型兼容模块，而不是在运行时允许任意 npm 安装。

HTTP 返回对象应兼容插件常用的 `status`、`headers`、`data`、`request` 等字段。所有兼容行为都需要用不包含真实密钥的本地假插件做契约测试。

若插件需要 Cookie，会话由宿主的按插件隔离 cookie jar 管理：不同插件不能共享，持久化内容必须加密并排除备份，断开授权时清除。脚本只能通过受控 HTTP 客户端间接使用 Cookie，不能读取其他插件或应用自身的会话。

## 7. QuickJS 轻量隔离

这里的“隔离”不是启动完整虚拟机，而是给每个插件创建独立 QuickJS 上下文，并只暴露完成音乐请求所需的最小能力。首版只运行允许列表中、由聆澜签名的脚本，因此 QuickJS 是进程内的能力边界和故障隔离层，不宣称等同于操作系统沙箱。安全性仍依赖 QuickJS 封装、桥接面和原生库本身；如果以后允许用户导入任意第三方脚本，必须升级为独立 Android 进程或更强隔离后才能开放。

### 7.1 允许的桥接能力

- 受控 HTTP/HTTPS 请求
- 必要的定时器
- 有脱敏和频率限制的日志
- 明确注册的 CommonJS 兼容模块
- 只读的插件运行参数，例如宿主版本和临时授权句柄

### 7.2 明确禁止

- Android `Context`、Java/Kotlin 反射和任意类调用
- 文件系统、相册、联系人、剪贴板和设备标识符
- SharedPreferences、数据库和应用内部目录的直接访问
- `file:`、`content:`、`intent:` 等非 HTTP 协议
- 对本机、局域网、链路本地地址和受限端口的请求
- 由脚本动态安装依赖或加载任意本地原生库

### 7.3 资源限制

- 每次调用设置执行超时、内存上限、响应体上限和重定向上限。
- 切换当前来源时取消旧来源的搜索和详情请求；旧上下文在没有进行中的调用后释放。已解析的当前媒体继续播放，队列以后需要旧来源时，在授权仍有效的前提下从私有缓存按需重建上下文。
- 断开授权、授权失效或脚本进入不可恢复异常后销毁对应上下文。
- HTTP 请求可以被取消；搜索框的新查询应取消旧查询。
- 插件连续崩溃时进入熔断状态，由用户手动重试或重新下载。
- 插件返回值先做结构、协议、URL 和大小校验，再进入应用模型。

网络限制必须在 DNS 解析后校验 IPv4/IPv6 目标，并在每次重定向后重新解析和校验，以防 DNS 重绑定或重定向进入私网。播放器取得媒体 URL 后使用同一套目标地址、协议、端口和重定向策略；不能因为请求已经离开 QuickJS HTTP 桥就绕过 SSRF 限制。代理行为、允许请求头和最大下载大小由宿主控制，脚本无权放宽。

脚本装载检查分两步：第一步在禁用真实网络的上下文中求值模块，检查元数据、导出方法和顶层执行是否越界；第二步使用宿主提供的固定 HTTP 响应执行契约探针。不存在“随意访问真实网络的健康检查”。只有用户首次发起真实搜索或浏览时才开始正常在线调用。

## 8. 密钥与授权生命周期

授权状态采用显式状态机：`DISCONNECTED`、`VALIDATING`、`ACTIVE`、`STALE_OFFLINE`、`EXPIRED`、`REVOKED` 和 `ERROR`。网络失败不能被当成密钥无效；只有服务端明确返回过期或撤销时才能进入对应状态。

### 8.1 连接流程

1. 用户在设置页输入购买的聆澜密钥。
2. 应用通过聆澜校验接口验证密钥，不以本地格式检查代替服务端验证。
3. 服务端返回有效期、授权状态和可用能力；应用保存最少必要信息。
4. 应用获取插件清单，过滤为允许的音乐来源。
5. 用户选择一个来源后，应用下载并校验对应脚本。
6. 脚本成功装载并完成一次无副作用的健康检查后，来源才标记为可用。

连接成功后记录服务端有效期和最后验证时间。应用启动、距离上次验证超过 24 小时、服务端返回 401/403，或用户主动刷新时重新验证。无法连接校验服务但本地有效期尚未到达、且距离上次成功验证不超过 24 小时时进入 `STALE_OFFLINE`，允许使用已验证缓存；超过任一边界后停止新的在线调用。具体时长应做成宿主策略常量，不能由脚本修改。

### 8.2 存储与展示

- 使用 Android Keystore 支持的加密存储保存密钥。
- 设置页只显示掩码和有效期，不提供复制完整密钥的入口。
- 禁止密钥进入日志、崩溃报告、备份、分析事件、截图辅助信息和文件名。
- 用户断开聆澜、清除数据、密钥到期或被撤销时，删除密钥及其个性化脚本缓存。
- 个性化脚本和会话存放在排除 Android Auto Backup 的目录中，并使用每个授权身份独立的 Keystore 密钥加密。断开或撤销时删除加密密钥，实现加密擦除，再删除缓存文件。

### 8.3 密钥传递原则

优先方案是聆澜返回短期下载令牌或让宿主通过安全请求头传递授权，而不是把长期密钥写入脚本文本或查询参数。如果现有服务只能返回含密钥的个性化脚本 URL，应当：

- 只在私有应用目录中下载和缓存；
- 对 URL、错误信息和网络日志做参数脱敏；
- 不从脚本文本中“提取密钥”；
- 正式联调前要求聆澜补充短期令牌、生产签名和脚本完整性摘要。

用户此前公开粘贴过的密钥应在继续联调前更换，设计文档和测试数据中不得复用。

授权失效后，不再解析新的播放地址；已经交给播放器的媒体流不主动中断，但 URL 失效后不会刷新。已完整下载到本地、且由应用正常记录的文件作为本地用户数据保留并可离线播放。新密钥按新的授权身份建立独立缓存，不复用旧密钥加密的脚本或会话。

## 9. 清单、来源过滤与脚本更新

可用于生产执行的清单项应包含：

```json
{
  "id": "stable-provider-id",
  "name": "显示名称",
  "version": "1.2.3",
  "url": "个性化或短期下载地址",
  "category": "music",
  "protocolVersion": 1,
  "minHostVersion": "1.0.0",
  "status": "active",
  "sha256": "必需",
  "signature": "生产环境必需"
}
```

来源过滤规则：

1. 首选服务端 `category == music` 或明确的能力声明。
2. 在当前清单尚无分类字段时，客户端暂时使用允许列表，仅接纳已确认的酷狗、酷我、QQ、网易云音乐插件。
3. Bilibili 和 GitCode 始终排除，不以显示名模糊匹配决定安全边界。
4. 未知来源默认不展示，等待应用更新或服务端补全可信元数据。

临时允许列表应匹配预置的清单主机、去除查询参数后的路径和精确来源类型组合；不能仅根据一个容易伪造的显示名放行。当前清单中的 `GitCode` 指插件条目，不是泛指 GitCode 托管域名。待清单提供稳定 ID 和分类后，删除该兼容规则。

生产环境执行远程脚本前，必须由经过认证的清单把插件 ID、版本和 SHA-256 绑定在一起，并验证由应用信任的聆澜签名密钥生成的签名。仅有 HTTPS 或“摘要与脚本从同一未签名接口返回”不足以作为完整性保证。签名公钥、轮换和紧急撤销规则必须在阶段 3 前确定；达不到该条件时，只能停留在本地假插件验证，不能发布远程脚本执行能力。

脚本更新采用“候选版本—验证—原子切换”：

1. 发现清单版本变化后下载到候选缓存。
2. 校验 HTTPS 来源、允许的主机、摘要、生产签名、脚本大小和元数据。
3. 在新 QuickJS 上下文中装载并做健康检查。
4. 成功后原子切换；失败则保留上一个已知可用版本并提示用户。
5. 不在验证前覆盖唯一的可用缓存。

清单状态至少区分 `active`、`mandatory-update`、`revoked` 和 `disabled`。普通更新失败可以回退到最近一个签名且未撤销的兼容版本；强制升级、版本撤销或安全 kill switch 生效时禁止回退。每个插件最多保留当前版和一个未撤销的上一版，避免多来源队列无限增加代码缓存。

缓存键使用用户授权身份的不可逆摘要、插件 ID 和版本组合，绝不使用原始密钥作为路径或文件名。

## 10. 设置页与交互

设置页增加“在线音乐来源”区域：

- 未连接：显示“连接聆澜”，允许输入密钥并查看隐私说明。
- 验证中：阻止重复提交，允许取消。
- 已连接：显示授权状态、到期时间、刷新和断开按钮。
- 来源列表：先根据已验证清单元数据和精确允许映射显示候选项，不预下载全部脚本；用户单选后才下载、校验和装载。
- 来源状态：显示“未安装、安装中、可用、需强制更新、已撤销或错误”、版本和上次更新时间，但不显示下载 URL。只有成功装载的选项才能成为当前来源；失败时恢复上一个当前来源。

切换来源时：

- 新搜索、新打开的在线页面和新添加的歌曲使用新来源。
- 当前正在播放的歌曲不被强制中断。
- 队列中已有歌曲保留各自的 `pluginId`；需要播放时，若旧上下文已释放，则先从该用户的私有缓存按需重建，缓存不存在时从当前已授权且过滤后的清单下载并装载该来源。按需装载不会改变搜索页当前来源；若旧插件已不可获取或授权失效，则明确标记不可播放。
- 仅在播放失败后按严格的歌名、歌手与时长规则匹配已加载来源；不符合规则时不切换，避免误播同名歌曲。

## 11. 关键业务流程

### 11.1 搜索

1. Repository 读取当前选中插件 ID。
2. 将查询、页码和搜索类型交给 `MusicProvider.search`。
3. PluginRuntime 调用脚本 `search`，规范化和校验结果。
4. UI 只展示该插件的结果，并保留来源标识。
5. 请求失败或结果为空时不查询其他来源。

### 11.2 播放

1. 队列项携带 `ProviderTrackKey` 和插件所需的受控附加字段。
2. 播放前按 `pluginId` 查找来源；内存中没有时先恢复私有缓存，缓存也没有时从当前授权清单按需安全装载。
3. 调用歌曲所属插件的 `getMediaSource`。
4. 对媒体 URL、协议、请求头和过期时间进行校验。
5. 播放器使用 `ResolvedMedia` 播放，不读取平台特定字段。
6. 解析失败时并行查询其他已加载来源；仅严格匹配成功才使用候选歌曲，并把后续歌词、收藏和历史绑定到该候选的真实来源。
7. 无严格候选或候选仍解析失败时，展示原来源错误。

### 11.3 封面与歌词

- 搜索结果自带封面时直接使用，并遵循图片缓存策略。
- 详情或歌词通过当前歌曲所属插件获取，而不是通过“当前设置中的插件”猜测。
- 插件未返回封面时使用默认封面；未返回歌词时显示“暂无歌词”。

### 11.4 授权到期或撤销

- 停止新的在线请求，销毁插件上下文并清理个性化脚本缓存。
- 不删除用户的本地音乐、本地歌单和历史元数据。
- 在线条目标记为暂不可用，用户重新授权后可按原 `pluginId` 恢复。

## 12. 本地数据与旧网易云数据迁移

旧数据以网易云 `Long` ID 为核心，不能无损转换为其他来源 ID。迁移遵循“保留用户数据、不静默误匹配”：

- 将旧收藏、历史和歌单条目转成只读的 `legacy-netease` 记录，保留标题、歌手、专辑、时长和封面缓存等已有元数据。
- 不在后台自动用标题和歌手匹配新来源，因为同名、翻唱、现场版和不同音质版本可能导致错误。
- 后续可单独设计“迁移到当前来源”工具：向用户展示候选歌曲和匹配依据，由用户确认后建立新 `ProviderTrackKey`。
- 本地文件使用独立的本地主键和 URI，不经过在线插件。
- 旧队列在升级后仍可显示，但无法解析的网易云在线项标记为 legacy 不可播放；当前已在播放的会话不参与数据库迁移保证，升级或进程重建后按持久记录恢复。
- 已完整下载且文件仍存在的歌曲迁移为本地文件记录并可继续播放；只剩远程地址、临时缓存或残缺文件的记录不视为有效下载。
- “只读 legacy”只表示不能修改其来源 ID 或假装已经映射；用户仍可删除、移出歌单、导出元数据和整理记录。

## 13. 与现有代码的衔接

以下是实施阶段的概念性改造范围，不在本次设计阶段修改：

| 当前模块 | 目标变化 |
|---|---|
| `NeteaseApi.kt` | 在线能力迁移完成后删除，不再直接调用网易云接口 |
| `MusicRepository.kt` | 拆分为本地资料库、插件在线资料库和播放解析服务，移除平台特定分支 |
| `Models.kt` | 引入来源感知的字符串 ID 和通用在线实体 |
| `PlaybackSource.kt` | 从硬编码枚举改为 `LOCAL`、`OFFICIAL`、`PLUGIN(pluginId)` 等可扩展来源 |
| `MusicSourceSettings.kt` | 扩展为授权状态、清单版本和当前插件选择的持久化入口 |
| `MusicSourceKeyValidator.kt` | 收敛为聆澜凭据验证客户端，不参与歌曲解析 |
| `UnblockManager.kt` | 删除网易云 ID 到聆澜/酷狗兜底链，由插件的 `getMediaSource` 取代 |
| `PlayerViewModel.kt` | 只编排队列和已解析媒体，逐步移走来源请求与平台专用缓存逻辑 |
| `NeteaseApp.kt` | 移除网易云 Cookie、Referer 和 API 初始化，最终改为中性应用入口名 |
| 包名和工程名 | 在功能稳定后独立迁移，避免与核心数据改造同时进行 |

简云自有内容只有在权利清晰时保留为 `OFFICIAL` 来源；它不通过聆澜插件，也不能伪装成第三方平台内容。

## 14. 分阶段实施顺序

### 阶段 0：基线与技术验证

- 为当前搜索、播放、收藏、历史和队列行为补充特征测试。
- 选定 Android 可用的 QuickJS 实现，验证包体积、ABI、生命周期和许可证。
- 使用完全本地的假插件验证 CommonJS、HTTP 桥和超时机制。
- 冻结 `JianyunMusicFreeCompat/1` 的参数、返回值、错误和分页契约。
- 在任何真实脚本联调前，确认聆澜授权覆盖脚本下载、设备缓存、运行时执行和预期分发场景。

### 阶段 1：通用模型与接口

- 新增 `MusicProvider`、`PluginRuntime`、通用实体和来源感知 ID。
- 为旧模型增加显式转换层，暂不改变现有 UI 行为。
- 先完成数据库 schema、备份和失败回滚测试；过渡期采用“旧数据只读适配 + 新操作写入通用模型”，不进行两套主键的无规则双写。

### 阶段 2：授权、清单和设置页

- 实现安全密钥存储、服务端验证、清单获取、来源过滤和单选设置。
- 暂不执行真实远程脚本，先用假清单和假插件完成 UI 测试。

### 阶段 3：插件宿主

- 实现 QuickJS 上下文、受控 HTTP、兼容模块、资源限制和脚本缓存更新。
- 通过假插件契约测试后，再使用轮换后的测试密钥做受控联调。
- 真实脚本联调的硬门槛是稳定插件 ID、签名清单、版本/撤销规则、授权状态机和聆澜运行授权全部确定。

### 阶段 4：首条完整链路

- 先打通“单来源歌曲搜索 → 播放地址解析 → 播放 → 歌词/封面”。
- 再接入专辑、歌手、歌单和榜单能力。

### 阶段 5：本地资料库迁移

- 迁移收藏、历史、队列、下载和歌单的数据主键。
- 保留旧网易云条目为 legacy 数据，不自动匹配。
- 将完整旧下载转为本地文件记录；旧在线队列项保留展示身份但不保证可播放。

### 阶段 6：移除平台耦合

- 删除网易云登录、Cookie、Referer、接口和专用响应模型。
- 删除硬编码聆澜/酷狗播放兜底链。
- 清理界面文案、资源名、包名和工程名中的网易云关联。

### 阶段 7：回归与发布准备

- 完整执行单元、集成、UI、离线、升级迁移和异常恢复测试。
- 检查 APK、日志、仓库和构建产物中不存在脚本、测试密钥或个性化 URL。
- 完成依赖许可证、聆澜授权范围、隐私说明和应用商店政策复核。

## 15. 测试策略

### 15.1 契约测试

- 为每个插件方法提供本地假脚本：正常、缺字段、错误类型、超大响应、超时和异常抛出。
- 验证 CommonJS 模块、HTTP 请求对象和返回对象的兼容行为。
- 验证插件缺少能力时 UI 正确降级。

### 15.2 安全测试

- 脚本尝试访问文件、Android 类、本地网络和非 HTTP 协议时必须失败。
- 验证执行超时、内存限制、响应体限制、重定向限制和取消。
- 扫描日志、崩溃报告、数据库、备份和缓存路径，确认没有明文密钥。
- 验证来源 URL、播放 URL 和错误消息的敏感参数被脱敏。

### 15.3 状态与升级测试

- 首次连接、错误密钥、过期、撤销、离线和重新授权。
- 清单刷新、脚本更新成功、更新失败回滚和旧缓存恢复。
- 切换来源时当前播放不中断，队列项目仍绑定原来源。
- 应用升级后旧收藏、历史和歌单不丢失，也不发生静默错误匹配。

### 15.4 播放测试

- 带自定义请求头、重定向、过期 URL、不同音质和不可用媒体。
- 无封面、无歌词、只有翻译歌词等降级场景。
- 后台播放、锁屏控制、网络切换、进程重建和耳机事件。

## 16. 验收标准

首个可发布版本必须同时满足：

1. 仓库和 APK 中不存在聆澜脚本、固定聆澜密钥和个性化脚本地址。
2. 未连接聆澜时，本地音乐和本地资料库可正常使用。
3. 用户可验证自己的密钥、看到允许的音乐来源，并单选一个来源。
4. Bilibili、GitCode 和未知来源不会出现在音乐来源列表。
5. 选择来源后可完成搜索、播放地址解析和播放；歌词与封面按能力降级。
6. 搜索和播放失败时不会自动调用另一来源。
7. 远程脚本不能直接访问 Android、文件系统或本地网络，并受时间和内存限制。
8. 来源切换不强制中断当前歌曲，队列歌曲不会丢失来源身份。
9. 旧数据被保留为 legacy 记录，不会在用户不知情时自动匹配。
10. 网易云登录、Cookie、Referer、专用接口及硬编码兜底链已从最终产品移除。
11. 所有生产脚本都通过受信签名清单验证，撤销或强制升级的版本无法被回退运行。
12. 数据库中的插件 ID 稳定且不含显示名、密钥、查询参数或临时令牌。

## 17. 正式联调前置条件

以下事项不阻碍使用本地假插件开发宿主抽象，但在接触真实脚本前必须书面或通过稳定接口确认：

- 清单能否提供稳定 `id`、`category`、能力声明、文件大小、协议版本、撤销状态和受信签名？如果短期不能，双方是否认可应用内置版本化稳定 ID 映射？
- 能否用授权请求头或短期令牌替代 URL 查询参数中的长期密钥？
- 能否提供不把长期密钥嵌入脚本文本的运行参数或短期访问令牌？
- 密钥校验接口的频率限制、到期字段、撤销状态和错误码是否稳定？
- 脚本下载、缓存、在用户设备运行以及应用商店分发场景是否在授权范围内？
- 插件协议版本如何演进，旧版本何时停止支持，如何发布强制更新或安全撤销？
- 聆澜使用什么签名算法和公钥轮换方式，应用如何获取并验证紧急撤销信息？

## 18. 已知产品空缺

当前首页、每日推荐或每周推荐中如有依赖网易云“相似歌曲”“推荐歌单”等专用接口的功能，不能直接沿用。MusicFree 常用插件协议也不保证提供相似歌曲能力。因此首版隐藏这些在线推荐入口，只保留本地最近播放、收藏和不需要平台接口的本地统计。

后续如需恢复推荐，应单独设计基于当前插件明确能力或本地行为的方案。在新方案完成前，不允许继续调用网易云接口作为隐形兜底。
